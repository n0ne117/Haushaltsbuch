# Haushaltsbuch

A deliberately simple, self-hosted income/expense tracker for one household. Mobile-first PWA, manual entry only, one Docker container.

See [docs/SPEC.md](docs/SPEC.md) for the full specification.

## Features

- **Erfassen:** amount → category → save, account remembered, undo toast. Due recurring bookings (Daueraufträge) appear on top: confirm ✓, edit ✎ or skip ✕ – never booked automatically.
- **Buchungen:** list grouped by day, search in notes, account/tag filters, edit/delete.
- **Statistik:** month/year/day views, drill-down per category, and the **Kreditansicht** (monthly averages over N complete months for a bank's Haushaltsrechnung).
- **Export:** CSV (Excel, de-AT), PDF statements (month/year) and Kreditansicht PDF.
- **Backups:** nightly at 03:00 to `/data/backups/`, last 14 kept.
- No login, no external requests, German UI.

## Setup on Unraid

The image is published to `ghcr.io/n0ne117/haushaltsbuch` for every release tag (`latest`, `1`, `1.0`, `1.0.0`).

1. Create the data folder (owned by `nobody:users`, the container's user) and a folder for the compose file:

   ```bash
   mkdir -p /mnt/user/appdata/haushaltsbuch /mnt/user/appdata/haushaltsbuch-compose && chown 99:100 /mnt/user/appdata/haushaltsbuch
   ```

2. Get the compose file and start:

   ```bash
   curl -fsSL -o /mnt/user/appdata/haushaltsbuch-compose/docker-compose.yml https://raw.githubusercontent.com/n0ne117/Haushaltsbuch/main/docker-compose.yml
   ```
   ```bash
   docker compose -f /mnt/user/appdata/haushaltsbuch-compose/docker-compose.yml up -d
   ```

   The app listens on port 8080. Database: `/mnt/user/appdata/haushaltsbuch/haushaltsbuch.db`. Migrations and seed data (accounts, categories) run automatically on first start – rename them under *Einstellungen*.

3. **Update** later:

   ```bash
   docker compose -f /mnt/user/appdata/haushaltsbuch-compose/docker-compose.yml pull && docker compose -f /mnt/user/appdata/haushaltsbuch-compose/docker-compose.yml up -d
   ```

To build from source instead, clone the repo and run `docker compose up -d --build` in it.

### Configuration (environment in `docker-compose.yml`)

| Variable | Default | |
|---|---|---|
| `TZ` | `Europe/Vienna` | Timezone for "today" and the backup time |
| `BACKUP_KEEP_DAYS` | `14` | Number of nightly backups to keep |
| `BACKUP_ENABLED` | `true` | Set `false` to disable the backup job |

### Reverse proxy (Caddy on OPNsense) – required

The app has **no authentication**. Only the reverse proxy may expose it, and only to the LAN and WireGuard subnets. HTTPS is also needed so phones can install it as an app (PWA/service worker).

In the OPNsense Caddy plugin: add a reverse proxy domain (e.g. `haushaltsbuch.home.example`) with an upstream to `<unraid-ip>:8080`, and attach an **Access List** that allows only your LAN and WireGuard subnets. The equivalent Caddyfile:

```caddyfile
haushaltsbuch.home.example {
    @outside not remote_ip 192.168.1.0/24 10.6.0.0/24
    respond @outside 403
    reverse_proxy 192.168.1.10:8080
}
```

Replace the subnets/IP with yours. Also make sure port 8080 on Unraid is not forwarded to the internet.

### Install on the phone

Open the HTTPS URL (over WireGuard when away), then *Teilen → Zum Home-Bildschirm* (iOS) or *⋮ → App installieren* (Android).

### Backups and restore

Every night at 03:00 the app writes a consistent copy to `/mnt/user/appdata/haushaltsbuch/backups/haushaltsbuch-YYYY-MM-DD.db` (SQLite online backup API) and keeps the newest 14. If the container was down at 03:00, a backup runs at the next start. *Einstellungen → Export & Backup* shows the last successful backup.

Point Restic/Backrest at **`/mnt/user/appdata/haushaltsbuch/backups/`** – never at the live `haushaltsbuch.db`.

Restore:

```bash
docker stop haushaltsbuch
```
```bash
cp /mnt/user/appdata/haushaltsbuch/backups/haushaltsbuch-2026-11-01.db /mnt/user/appdata/haushaltsbuch/haushaltsbuch.db && rm -f /mnt/user/appdata/haushaltsbuch/haushaltsbuch.db-wal /mnt/user/appdata/haushaltsbuch/haushaltsbuch.db-shm && chown 99:100 /mnt/user/appdata/haushaltsbuch/haushaltsbuch.db
```
```bash
docker start haushaltsbuch
```

## Development

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest
DATA_DIR=./data .venv/bin/uvicorn app.main:app --reload --port 8080
```

PWA icons are generated by `scripts/make_icons.py`.

Releases: push a tag `vX.Y.Z`; `.github/workflows/docker.yml` runs the tests and publishes the image to GHCR.

Schema changes: edit `app/models.py`, then `.venv/bin/alembic revision --autogenerate -m "…"` and review the generated file in `app/migrations/versions/`.

## Privacy – no financial data in this repository

Real financial data (IBANs, account/card numbers, real amounts, the database, backups, CSV/PDF exports, `.env`) must never be committed.

Safeguards:

1. **`.gitignore`** excludes databases, backups, `data/`, exports (`*.csv`, `*.pdf`, …) and `.env*`.
2. **Git hooks** in `.githooks/` run `scripts/check-personal-data.sh`:
   - `pre-commit` checks the staged changes,
   - `pre-push` re-checks every commit being pushed (also catches `git commit --no-verify`).

   They block forbidden file types, IBAN-like strings, and strings from your local `.personal-patterns` blocklist.

After every fresh clone, enable the hooks:

```bash
git config core.hooksPath .githooks
```

Optionally create `.personal-patterns` (gitignored) with one string per line – account, card or depot numbers etc. that the IBAN check wouldn't catch. Matching is case-sensitive and whole-word.

Test fixtures that need CSV files go in `tests/fixtures/` and must use made-up data only.
